# Release acceptance

1. Desktop and mobile: new public page renders, packages and full scope are readable, form works with keyboard, and no horizontal overflow or script errors occur.
2. A selected package prefills; invalid keys cannot invent packages or prices. Public assessment POST returns a real receipt and persists structured problem/outcome/constraints/budget/deadline in the protected inbox. Wrong kind, missing outcome and forged package return 400. Wrong origin and unauthenticated private calls remain denied.
3. Private customer request persists package preference. Customer cannot see preparation controls or call draft endpoint. Owner can read the authorised request and prepare a review-required draft. Nonexistent request returns 404; no proposal is issued by drafting. Revoked and cross-tenant boundaries continue passing existing database/HTTP suites.
4. Exact proposal acceptance plus full net payment is required for delivery activation. Refunds, wrong currency, crafted identifiers, stale hash and direct customer payment recording remain denied by existing commercial tests.
5. Builds, marketing source boundary, CSP/SRI, fixture/secret exclusion, migration verification, dependency audit and existing access tests pass.
6. Higgsfield API request completes with a usable output and recorded request evidence before claiming media generation. Inspect downloaded media and mobile/reduced-motion fallback before publishing.
7. Production owner accepts invitation, verifies email, completes guarded account provisioning and MFA, then authenticated production journeys pass. Invitation alone does not establish owner access.
8. Marketing release uses reviewed exact pushed source and the correct production Vercel project. Private OS release is separately verified. No untracked originals, private research or local credentials enter artifacts.

Outstanding hosted dependencies must remain recorded in progress/handover. Passing fixtures is not proof of production payment, provider connection or customer onboarding.
