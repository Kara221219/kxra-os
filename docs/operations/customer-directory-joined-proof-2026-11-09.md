## Application lifecycle boundary and limitations

Installed Next16.4.3 glossary documents that pages are reused on Back/Forward even when default dynamic-page caching is zero; the installed staleTimes guide explicitly says changing staleTimes does not alter that behavior. Force-dynamic/no-store/prefetch=false alone therefore did not cover browser history.

Directory entry, pagination, refresh and exits now use ordinary document anchors/forms, preserving keyboard and modified-click browser behavior without global router/cache configuration. A small route-only client boundary initially conceals SSR metadata; it installs pagehide/pageshow/popstate listeners before revealing the fresh server document. Pagehide conceals and removes the metadata DOM. Persisted restoration or document-history events keep it concealed while requesting a fresh document and re-running the unchanged authority path. Fragment-only skip navigation remains native. No client predicate grants permission or marks restored data current.

No-JS and failed hydration leave the display concealed with an explanation/status. We do not assume pagehide ran before hydration: initial concealment is deliberate. This is presentation/history protection, not a replacement for server authorization or a claim to erase data already delivered to an authorized browser. Real browser Back/Forward, keyboard, modified-click, exits, no-JS and blocked-hydration cases are prepared; pure listener tests are not substitutes for their execution. Safari and all browser-specific BFCache behavior remain unproved unless separately exercised. Exact-head production budgets and final aggregate checks remain required; no cap is raised.
