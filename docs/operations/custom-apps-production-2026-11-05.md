## Actual gap and implementation

The integrated head already supplied immutable declarative schemas/versions, transient sandboxed previews, publication pointers/history, typed persistent records, append-only record revisions, exact retry receipts and local recovery. Those mechanisms were not rebuilt. The remaining path required fixture identity in HTTP and SQL, lacked an independent review transition, and had no hosted workspace navigation.

The existing API/customer routes now admit a verified Supabase Actor only when `KXRA_CUSTOM_APPS_ENABLED=true` and a separately retained verified provider session-version equals the current account version. The default is off. The shipped Next route still obtains `actor()` itself; injectable identities exist only in the disposable test adapter. No caller ID, role, approval, paid proof or execution-mode field is accepted in mutation bodies. Same-origin, strict bodies, bounded sizes and private/no-store responses remain in place.

The server captures only a verified top-level `kxra_session_version` claim from `getClaims()` into `provider_session_version`. It never reads user/app metadata for this authority. This is distinct from `account()` loading the current database version. The DB request GUC is set only from verified server context and configuration, and SQL independently compares both versions with the active account. Missing/stale claims fail closed.

The unnumbered `database/production/custom-apps-v1.sql` installs six RLS tables and fourteen functions, preserving the typed engine and local-only release guard. New append-only review decisions pin the exact immutable artifact digest and version. Another administrator in the same tenant must review using recent existing owner MFA and room write access. Current approval requires unexpired APPROVED state, current reviewer account/session/admin membership and private-room access. Approval expires after 24 hours; withdrawal/rejection and authority changes prevent new saves/publication. Historical records remain readable to currently authorized paid room members. Review decisions increment app revision, making concurrent stale controls fail.

Production PUBLISH/ROLLBACK use reviewed versions; rollback requires a prior reviewed release. New saves require the current published schema and valid review; exact committed retries preserve their original receipt. There is no external hosting or arbitrary-source execution. Preview entries remain ephemeral and cannot reach records, network or privileged capabilities.

Workspace navigation is enabled from server capability, and the builder exposes independent review plus production publication/rollback controls. Customer form access and record history continue through the existing separate client route. Expired/withdrawn reviews display REVIEW REQUIRED and make record controls read-only.

## Independent review and remaining live gates

Independent read-only review found and verified fixes for stale session authority, authority revocation races, continuing reviewer room access and hosted navigation. The final review reported no remaining concrete high/medium code defects. Review validity display was also corrected.

A trusted Supabase token hook/session attestation is NOT provisioned here. It must bind the ORIGINAL provider session to the account authority version and preserve that version across refresh, or reject revoked session IDs. Stamping the current database version onto every refreshed old session would revive stale authority and is unacceptable. Real getUser/getClaims/session refresh/MFA and end-to-end hosted browser acceptance remain gates. The fixture injects synthetic already-resolved Actors only in its adapter and makes no provider calls.
