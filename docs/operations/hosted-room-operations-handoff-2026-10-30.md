## Existing lifecycle to preserve

Migration0087 already implements durable jobs/attempts, authenticated scoped reads, immutable pinned context, idempotent enqueue, three-attempt predispatch retry, leases, guarded dispatch/completion, cancellation and reconciliation. A lost postdispatch outcome becomes UNCERTAIN instead of automatic provider replay. Migration0088 adds immutable daily definitions, explicit review, timezone/DST rules, per-local-day unique occurrences, bounded budgets, no overlap, expiry, latest-day catchup and source/authority withdrawal fences.

Important integration constraint: these RPCs explicitly require `session_user='kxra_app'` and use `auth.uid()`/current member organisation/requester identity, including0087 `team_job_ready`, enqueue, claim, release/dispatch and0088 `team_schedule_tick`. Claims are actor+tenant scoped, not a global anonymous queue. Merely granting EXECUTE to a worker role or calling existing HTTP drain with a scheduler bearer cannot make that role an authorized requester. Do not remove these checks globally or give an all-tenant service-role bypass.

`apps/os/lib/team-jobs.ts:159` currently performs tick→one45second claim→prepare pinned context→`executePreparedTeamAgent`→bounded predispatch release. Its provider execution uses the existing room agent/connection and run publication path. Reuse that lifecycle; do not invent new agent creation, connectors, model features or external actions.

## Narrow implementation handoff for operations engineer

1. Keep existing user/room/API access and reviewed daily definitions. Add an explicit default-off hosted capability and a narrow worker authentication/configuration boundary. Keep fixture launcher unaltered and production fixture rejection intact. Activation only follows separately reviewed deployment/identity approval.
2. Define server-verifiable durable execution authorization for the existing requester, tenant, room, definition/job and selected provider connection. It must be issued from existing authenticated review and revocable on membership, account/session policy, paid entitlement, connection or source withdrawal. Never accept arbitrary actor/tenant from a wakeup body or use a browser access/refresh token as scheduler credentials. Resolve actor authorization from stored scoped grant, recheck on claim/dispatch/publication, and record opaque audit receipts.
3. Add narrow claim/tick/dispatch/finish capabilities for that verified worker scope through additive reviewed migrations/ACLs; preserve existing authenticated behavior and database authority. A worker may discover only authorized due scopes. Fair bounded discovery, lease expiry/reconciliation, duplicate wakeup and concurrency must be proven across requesters/tenants. Provider output still passes the existing run/room/publication fences.
4. Package one bounded wakeup/worker endpoint or process with verified configured identity, provider deadline shorter than its lease/budget, graceful cancellation and sanitized health/backlog/error metrics. Prove actual protected-host delivery and recurrence. No new provider, credential or deployment is created by QA. Reuse approved infrastructure where sufficient; return a concrete identity/configuration proposal before activation.
5. Enable hosted enqueue/propose/review only after that path exists and acceptance passes. Permit authorized PAUSE/REVOKE/cancel during rollout holds or worker suspension so stop controls do not disappear with admission. Update capability-based UI wording/control availability and readiness output to the measured scope; do not falsely set provider acceptance true from configured keys.

The smaller launch alternative is to sell only the already supported, genuinely verified on-demand room workflow and explicitly exclude unattended/recurring execution. That is a product-scope decision, not an engineering bypass. Parent owns that decision with the actual offer. If existing scheduled drafts are required, steps1–5 are the narrow missing infrastructure rather than a new product feature.
