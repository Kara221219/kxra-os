## Implemented authority

`database/production/custom-app-session-attestation-v1.sql` is an unnumbered review payload after the exact existing production custom-app cohort. A private immutable binding records each newly inserted `auth.sessions` ID, original account ID, provider creation timestamp and original application account session-version. It uses the existing exclusive authority statement fence before capture. It does not backfill existing sessions and the hook cannot create or update bindings. Session IDs cannot be reinserted after deletion; provider ID/user/creation-time updates are rejected.

A session created before installation has no binding. A missing application identity or null provider creation timestamp produces a permanent unbound tombstone. Those cases require fresh sign-in. An already existing pending/unverified application identity can bind its current version at session creation; its hook output remains unprivileged until that same identity becomes ACTIVE and verified without a version change. No later refresh fills an absent version or upgrades an old binding. This distinction is intentional and tested.

`kxra_private.custom_app_access_token_hook(jsonb)` is callable only by `supabase_auth_admin`. It preserves standard claims and metadata, removes the incoming top-level `kxra_session_version`, and adds the original version only when the binding, current provider session/user/time, current account/version/state/verification and `not_after` remain valid. Metadata is preserved but never used for authority. Malformed events and inputs over 65,536 bytes fail closed. No application/Data API role can invoke the hook or read/write bindings.

The existing server `principal()` now delegates its unchanged getUser/getClaims subject-match and MFA-time checks to a separately tested resolver. The additional provider session ID and original version come only from the verified top-level claim payload. `account()` can still load the current DB version, but cannot overwrite the original provider version. DB request context includes the verified session ID only for Supabase principals.

The payload replaces the ORIGINAL `custom_apps_access()` function definition, retaining its OID and existing RLS dependencies/ACLs. Its exact prior paid/legal/tenant authority is retained in a private, uncallable helper and combined with the original-session check. Thus even a synthetically signed token claiming the current version cannot substitute a foreign, deleted, expired or old-bound session. Room/tenant access, MFA review, independent schema review, paid entitlement, immutable publication/records and fixture-only authority remain unchanged. The same shared/exclusive authority fence serializes account/session revocation with custom-app mutations; no automatic retries were added.
