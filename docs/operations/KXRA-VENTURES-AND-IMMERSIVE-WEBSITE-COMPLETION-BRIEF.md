## KXRA public experience

### Creative direction

Build an original KXRA journey. Do not reproduce AI Builders, Pomelli, Scroll Craft or another site's scene sequence, assets, copy, geometry or interaction. References provide principles only.

The experience should feel like moving through an intelligent operating system that can enter different industries while retaining one disciplined core. Use the existing KXRA palette as the starting brand language: deep forest, paper, mineral white, charcoal and a restrained acid-lime signal. Prefer sculptural light, physical materials, diagrams, fields and data planes over neon, glass-card clutter or humanoid AI imagery.

The camera is useful only when it clarifies the story. Text and controls remain semantic HTML. WebGL is progressive enhancement and never owns essential navigation, content or forms. The page must remain complete with JavaScript unavailable, reduced motion enabled or WebGL unsupported.

### Journey

1. **Threshold — Context.** Begin in a quiet architectural space containing a single KXRA signal object: a dark monolith or instrument table with a living portfolio map. Headline: “Ideas become operating businesses here.” Supporting line: “KXRA combines evidence, controlled AI and human judgment to build useful tools and ventures.” Primary CTA: “Bring us a business need.” Secondary CTA: “Explore KXRA OS.”
2. **Portfolio field — Connections.** As the visitor advances, the portfolio map expands into connected industry territories. Show sanitised capability worlds, not confidential project data: Property & Places; Health & Care; Commerce & Production; Mobility; Media; Technology. Explain that one operating core connects evidence, people, tools and decisions.
3. **Property & Places.** Move through accurate spatial capture, property presentation, hospitality operations and approved listing workflows. Show opportunities without claiming KXRA manages properties or has customers. Emphasise rights, fidelity and local compliance.
4. **Health & Care.** Enter a precise, calm clinical environment based on pathways, accountability and consent. Do not advertise treatment, name unverified clinicians or imply registration. Explain that regulated ventures require qualified professionals and hard stops.
5. **Commerce & Production.** Travel through a material lab containing fitment, wall-print, product and fulfilment evidence. Show how KXRA tests supplier claims, safety, landed costs and demand before launch.
6. **Mobility.** Present vehicle inventory and customer conversations as verified data flowing into a human-approved sales desk. Never show autonomous persuasion, fabricated inventory or finance advice.
7. **Media & Technology.** Reveal governed content production, repository intelligence, Brand Studio and Ask KXRA. Show source lineage, rights, run logs, permissions and approvals as visible parts of the environment.
8. **Operating core — Control.** The worlds converge into the eight KXRA controls: Context, Connections, Capabilities, Cadence, Control, Confidence, Compliance and Continuity. Make project isolation, evidence, approvals and auditability understandable to a nontechnical buyer.
9. **Outcome — Build with KXRA.** Resolve into a simple, fast final scene with two routes: subscription tools for recurring work and separately scoped custom projects. Use only approved pricing and availability. Until those exist, label tools “Private preview” and custom projects “Discovery open.”

### Content rules

- Use no invented revenue, customer, member, launch, conversion or project-count claims.
- Use no fabricated testimonials, logos, screenshots or case studies.
- Internal project names and supplier references are private unless a separate publication record approves them.
- Every public proof item needs source, rights, date, approval state and publication version.
- Generated visuals are supporting atmosphere, never evidence of a real product, property, patient outcome or customer result.
- Keep `info@kxra-group.com` as the public contact.
- Keep the public marketing app isolated from private OS routes, cookies, database role and build artifact.

### Motion and interaction

Use one master progress model with reversible scroll. Most movement is forward with restrained lateral reveals. Use acceleration only for transitions. Avoid constant rotation and parallax sickness. Provide keyboard-equivalent navigation, visible focus, pause controls for autonomous media and no scroll hijacking that traps the user.

Desktop may use React Three Fiber/Three.js and GSAP only if the implementation satisfies budgets. Lenis is optional and must be removed if native scrolling gives better accessibility or input latency. Mobile uses fewer objects, shorter paths, static poster frames and CSS transforms. Reduced-motion mode shows the same narrative as normal document flow.

### Performance budgets

- Preserve the existing automated Lighthouse thresholds and strengthen them only with measured evidence.
- Keep initial critical content server-rendered.
- Do not load the 3D runtime before the hero's readable HTML is available.
- Lazy-load secondary scenes and video; pause off-screen loops.
- Use compressed, rights-cleared AVIF/WebP images, MP4/WebM video and glTF/GLB models with measured dimensions.
- Cap device pixel ratio and object density by device capability.
- Record bundle, texture, model, video, GPU and memory budgets before implementation.
- A static/mobile fallback must pass even when WebGL creation fails.

## Higgsfield and Seedance 2.5

The repository uses TypeScript and npm. The official `@higgsfield/client` package is installed. `scripts/higgsfield-seedance-example.ts` uses the official server-only v2 client and model `bytedance/seedance-2.5/text-to-video` with the requested prompt, five-second duration, 720p resolution and 16:9 ratio. It reports success only when status is completed and `video.url` exists; failed, cancelled, moderated/NSFW and incomplete responses fail.

Credentials remain in ignored `.env.local` as `HF_CREDENTIALS=KEY_ID:KEY_SECRET`. Never place them in chat, Git, browser code, `NEXT_PUBLIC_*`, logs or Vercel's public environment. The example also requires `KXRA_HIGGSFIELD_BILLABLE_CONFIRMATION=GENERATE:SEEDANCE-2.5:5S`. This prevents builds, tests and accidental commands from creating chargeable media.

Before the one-off billable verification:

1. The owner creates or selects a Higgsfield API key with the smallest appropriate scope and confirms account billing limits.
2. The owner enters both values locally in `.env.local`; Codex must not read or display that file.
3. Review the exact prompt and current provider price in the Higgsfield console.
4. Run `npm run higgsfield:seedance:example` once.
5. Record only request status, model, input hash, cost/usage if returned and the output URL or failure class. Do not record credentials.
6. A successful URL proves this example only. It does not approve bulk asset generation or production provider access.

Generated website assets require an asset brief, rights/provenance record, public-content approval and a maximum generation budget. Create a small coherent set: threshold ambience, industry transitions and screen loops. Do not generate fake founders, customers, clinicians, properties, vehicles or results.
