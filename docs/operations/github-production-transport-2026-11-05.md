## Implemented backend contract

`packages/connectors/github-production-contracts.ts` defines strict server-owned bindings for tenant/user/connection, session/grant/credential epochs, App/installation/account/repository/issue/bot IDs, canonical names and expiry. It accepts only finite typed repository, issue, bounded comment-page and exact comment operations; it never accepts a URL, method, header, credential or identity from an operation body. The approval hash binds the full connection authority, write UUID, exact body and approved/expiry times. The operation hash also binds the dispatch attempt. Unknown fields are rejected. This is a new contract; casting an old fixture payload or reusing its differently computed SQL digest is not a migration strategy.

`packages/connectors/github-production-transport.ts` defaults off through server-only `KXRA_GITHUB_PROVIDER_ENABLED`. It is not imported by any production route. Even setting that flag does not implement a broker, worker, installation or SQL grant; existing routes remain503. Trusted backend/test seams cannot be supplied by a browser/model request.

The real Node implementation pins HTTPS443, `api.github.com`, SNI and certificate verification, disables connection-pool reuse, resolves IPv4 answers once, rejects every nonpublic/mixed/empty answer and pins the accepted address to the socket. Request paths come only from the binding and operation; redirects, proxy URLs, alternate origins, arbitrary verbs and token endpoints are unavailable. It never issues, refreshes, signs or revokes a token. The broker must resolve an **existing** purpose-specific installation lease with exact binding hash, reference/version, App/installation, one repository, Metadata:read and Issues:read or Issues:write. A write token is not accepted as a read lease. The known old fake token is denied by its SHA256 value so its literal does not enter a future production bundle; the old fixture transport/token restrictions remain unchanged.

The IPv4 utility was extracted without changing its blocklist or existing AI provider export/behavior. It avoids importing the AI provider implementation into the connector. Current provider regression tests must remain passing.

Authority is re-read before broker resolution, after it, after DNS, and before I/O; expiry, cancellation and enablement are checked after asynchronous authority waits too. Private read results are re-authorized before release. Repository/account/canonical-name and numeric issue identity are checked; pull requests are refused. Responses project only necessary IDs, names or bounded untrusted comments. Repository clone tokens, raw responses/errors, headers and bearer values are not returned or logged.

A comment needs recent successful repository and issue checks in the same execution window, exact approved payload/digest, at most five-minute approval validity and an already committed exact dispatch claim. It additionally requires `authority.consume`: an atomic, irreversible consumption of that attempt, including fresh authority in the same transaction. Its exact acknowledgment is followed by fresh authority/lease/expiry checks. Any write refusal before confirmed exclusive consumption, including failed, lost or timed-out consumption, returns `REFUSED`, never a claim that another worker did not execute. Only a positively acknowledged exclusive consumption followed by a known pre-HTTP stop can yield `NOT_EXECUTED`. Consumed/uncertain attempts must never be reset by recovery. The transport's own one-write flag is only an additional process-local guard.

After request construction, failures conservatively become `UNCERTAIN` for writes. Matching201/body/bot/issue acknowledgments produce sanitized historical acceptance evidence even if current authority is subsequently withdrawn; receipt recording still needs the separate receipt-only DAO. Documented JSON rejections are sanitized. Redirects, malformed/oversized/stalled responses, transport errors, wrong acknowledgments and ambiguous server failures never retry. A consumed attempt cannot be repeated within the object; reconstruction is safe only when the mandatory external consumption port obeys its atomic contract.

Each serial execution window lasts at most30seconds and allows six calls, including at most one comment attempt. Each complete operation, including authority, lease resolution, DNS and response body, has a deadline capped at the existing two seconds. Bodies cap262,144bytes and512 data events. Explicit identity encoding prevents compressed-body ambiguity. Read pagination allows only numeric pages1–3; Link URLs are validated but never followed. A third page with a next link remains incomplete, and absence is never nonexecution proof. Write preflight is valid for at most10seconds. A later human approval should use a fresh dispatch window; this is not a five-minute socket lease.

Rate evidence contains only normalized stop/not-before/reason fields. Quota exhaustion, Retry-After and403/429 stop the window, including malformed response bodies. Invalid controls also stop it. No sleeps, automatic retries, token renewal or global rate-limit claim is introduced. Production workers must persist and coordinate account/App budgets across windows.

## Verification and evidence boundaries

`tests/github-production-transport.test.ts` uses in-memory trusted ports and synthetic material only. It covers fixed destination/TLS options, binding/lease scope and epoch mismatches, secret-safe projection/errors, authority drift across waits, exact approvals, competing reconstructed executors, consumption acknowledgment loss/timeouts/revocation, no late send, post-send uncertainty, provider rejections, rate stopping, byte/encoding limits, pagination, call budgets and concurrency.

`node scripts/verify-github-production-transport.mjs` runs an exact committed clone with an owned native fixture lease. Its native proof generates an ephemeral self-signed test certificate/key and fake bearer inside an owned directory, uses only a127.0.0.1 TLS fixture and an explicit trusted request seam, then removes the generated files after server/socket/port cleanup. The seam asserts the original fixed destination, TLS/SNI and pin options before routing to loopback. No real DNS lookup, GitHub certificate, account, credential or provider call is accepted by that test. Positive/comment-loss/reconstruction/withdrawal/deadline/size/rate/untrusted-certificate cases exercise real Node TLS. Cleanup waits for every tracked socket close event and requires a zero socket count before declaring success; independently review found and corrected an earlier receipt that reported clean while a close event was still pending. The shared test consumption store survives executor reconstruction, **not a production SQL crash/restart**. Native results cannot establish durable production consumption, managed custody or live acceptance.

Independent review identified that an object-local one-attempt flag alone is insufficient across reconstruction. The required atomic-consumption port, conservative lost-ack handling and competing-executor tests address that interface gap; a production durable implementation remains explicitly absent. Final source-specific logs, native cleanup, build/budget/artifact scans and independent evidence review are retained outside source in task acceptance-evidence. No older results are relabeled as this head's execution.
