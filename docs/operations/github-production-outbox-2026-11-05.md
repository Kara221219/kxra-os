## Authority and immutable lifecycle

Nine private RLS tables hold activation, immutable account/installation/repository/issue binding, read evidence, exact write proposals, attempts, purpose-bound capability hashes, irreversible consumptions, historical receipts and uniquely attributed external effects. There are no new sequences. Direct table access and private helper execution are denied to application, authenticated, anonymous, billing and AI worker roles. Only three checked functions are callable through the authenticated role, and each verifies `session_user='kxra_app'`. Definer functions use an empty search path and qualified relations. An administrator remains trusted; this is not a defense against a database owner disabling triggers.

A trusted scoped read worker records a digest as testimony, not independent proof of a provider read. A human proposal freezes target, exact body, read evidence and expiry. The server appends a write UUID marker. A separate verified human operation with current MFA must attest to the exact proposal digest; its actual approval timestamp then derives the reviewed transport approval digest. Enqueue and claim cannot edit payload or extend expiry. Agent/device tokens, customer cookies, read workers, dispatch workers, attempt dispatch and receipt capabilities are distinct purposes in one hash namespace.

Claim commits an immutable attempt before returning its random dispatch/receipt handles. The adapter returns a consumption acknowledgment only after COMMIT. A unique consumption row permits one acknowledgment for an attempt; repeat consumption is denied, including after a lost acknowledgment or database restore. Claim never requeues an uncertain attempt or mints a second attempt for an already claimed write. Cancellation before claim stops it; after claim it records a request and prevents a new consumption while retaining uncertainty about a possible effect. Recovery changes DISPATCHING to UNCERTAIN and never resets consumption.

Authority checks use current tenant membership, verified account/session epoch, owner role, business review, exact legal acceptance, live paid proof and the connection/capability/approval deadlines. The independent `kxra-ghp-authority-v1` advisory fence is shared before outbox row locks. Pre-statement exclusive triggers fence all mutable authority dependency tables, including phantom legal requirements, latest declarations and invitation seat counts. Existing authority row locks are not taken by the outbox; this avoids inversion with existing review routines and avoids upgrading their separate shared policy fence. Only new outbox connection/write/capability/activation rows use row locks. Capability deadlines are rechecked after fence waits. The approval actor is checked against the immutable connection owner; no redundant account FK is added to the approval history, avoiding an implicit FK lock cycle with review operations.

The writer-trigger inventory is deliberately broad and exact in the retained catalogue. It serializes authority changes globally for this first boundary. A later optimization must preserve the same phantom/withdrawal ordering and be separately reviewed; it may not simply remove these fences. PostgreSQL statement timeouts bound waits and no automatic SQL/provider retry is introduced.

## Receipts and recovery

A separate receipt-only capability can publish bounded, exact historical evidence for its consumed attempt after account, grant, connection or feature withdrawal. It confers no read, vault or send authority. Duplicate identical evidence is idempotent; conflicting payload/target/comment evidence and reuse of one provider effect across attempts are denied. A provider-uncertain result cannot later be relabeled definitely unexecuted or rejected. Matching reconciliation can resolve it to accepted. REFUSED is never converted to a historical NOT_EXECUTED receipt.

Receipt contents remain trusted backend-worker testimony checked against the stored attempt, not cryptographically authenticated GitHub evidence. The receipt capability is therefore an execution-system credential and must never be given to an agent, browser or customer. A live reconciliation worker must first independently verify exact GitHub account/repository/issue/body/bot identity.

Attempt handles redact normal JSON/inspection output. Raw random capabilities are sent only through bound transaction-local settings; durable SQL stores their hashes. `escrow(seal)` is an explicit trusted custody port, not an implemented production escrow service. The fixture uses protected temporary synthetic recovery material and deletes it during cleanup. A production encrypted durable escrow and authenticated worker identity are still mandatory before activation, including handling a claim COMMIT acknowledgment lost before escrow. Such a loss strands an attempt safely rather than retrying it.

The native proof retains an unreceipted consumed fake effect, gracefully restarts PostgreSQL, then dumps/restores the entire installed extension set into a verified-empty template0 database. Exact definitions, owners, ACLs, private rows, sequence state, and both migration ledgers must agree. A reconstructed consumed attempt issues no additional fake POST. It reconciles the existing exact fake effect, withdraws all current authority, then publishes a matching historical receipt without restoring read/send access. This proves local same-cluster restart and fresh-database restore, not forced power-loss, independent-cluster/role, hosted recovery or real-provider behavior.
