## What this slice supplies

`paired-setup-policy-v1.sql` is an unnumbered, unwired proposal after genuine AI118 and the accepted paired authority proposal. It adds an empty, disabled-by-default paired transport policy registry and five-minute setup requests. An authenticated customer ORG_ADMIN with current AAL2, server session/version, active organization/project access and explicit room membership can request a **disabled private agent**, inspect a safe status or cancel. Requests are owner/session/membership/room/AI-intent scoped; idempotency accepts only identical requests, cancellation/expiry cannot reopen them, and pending request capacity is bounded. No pairing invitation, bearer token, credential, device session, persistent access grant or activation is issued. Setup request IDs are selectors, never authentication.

Policy evaluation composes existing current legal acceptance, authoritative paid proof, business eligibility and latest provider-specific AI review. The selected OPENAI intent must belong to the same owner, organization and server session, with current CUSTOMER_BILLED review. API-key use additionally needs an independently reviewed, expiring paired transport policy; no policy row is seeded or enabled by installation. Existing AI review is not interpreted as commercial permission for paired transport. ChatGPT-subscription requests always return `SUBSCRIPTION_PROVIDER_CONFIRMATION_REQUIRED`; no subscription permission is inferred.

A request captures immutable review/terms/policy/account/model bindings; changed evidence needs a new request. Paid proof freshness is rechecked, not grandfathered. `POLICY_READY_SETUP_HELD` explicitly has `activation_allowed:false` and `credential_issued:false`; it is not runtime or commercial acceptance.

The composed predicate replaces the RLS policy and public consumption wrapper. Renamed storage predicates/mutators lose authenticated EXECUTE, preventing an old-function/OID bypass. A dedicated advisory read/write fence serializes short consumption transactions against policy-source mutations. Request/cancel operations take the exclusive side up front, avoiding shared-to-exclusive upgrades. No fence/transaction spans provider work or external I/O. Permit expiry is bounded by setup, transport, paid proof/period/freshness, AI intent/review, business review/policy, owner MFA and organization membership expiry, as well as the accepted storage-layer bounds.

`PairedSetupStore` consumes a verified server principal separately from strict request selectors, runs authenticated RLS transactions and hides pool/authority metadata. The injectable `pairedSetupHttp` helper defaults503 before identity/pool discovery; it enforces POST, trusted origin, JSON, bounded request bytes, identity and strict commands. It is deliberately **not wired to a hosted Next route or UI**. Production 503/404/manual/native/installed-CLI guards are unchanged. Real Supabase cookie/session resolution is a later hosting integration step; generated fixture principals are not live authentication acceptance.
