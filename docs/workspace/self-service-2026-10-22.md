## Implemented boundary

`/signup` and `/api/signup` create an identity through the existing local synthetic Auth adapter, deliver a synthetic verification message and create no application account, organisation or membership until verification. The provider adapter's existing `registerInvited` method supplies account/password/token mechanics only; this path creates or redeems no invitation. Passwords remain with that adapter and never enter provisioning tables or receipts. Correct same-password retries can resend verification; registered identities recover through sign-in.

Verification creates a server-validated session. Provisioning takes only a request UUID and workspace name; no caller-selected user, organisation, project, role or paid status is accepted. An atomic identity lock creates one CUSTOMER organisation, ORG_ADMIN membership, initial project/contributor scope, onboarding progress and preferences. Unique identity/request receipts recover duplicate/lost acknowledgements and reject changed names, reused foreign requests and existing unrelated accounts. The existing nine onboarding steps are reused, including profile, access, preferences and legal checks. No platform-owner role or legacy global owner projection is created.

Additive local migration0093 records the provisioning receipt under RLS and closes the legacy-entitlement exception for all newly self-provisioned organisations. New work remains blocked without an accepted pilot record. Existing legacy organisations are unaffected. Synthetic entitlement in the browser test is deliberately seeded by the disposable database harness; it is not a checkout success, charge, webhook or customer-access activation endpoint. The test then exercises actual room/message writes and reload/session recovery.

The constructor is internal, SECURITY DEFINER for this narrow multi-table transaction, with empty search_path, revoked PUBLIC/anon execution and a fixed return shape. It requires the application database login, verified server identity and a local-only admission setting set by `packages/db` only for a fake-provider session in the guarded local environment. User metadata never sets that admission. Production import conditions hard-disable the local guard; supplying fixture environment flags cannot enable the built production route. The existing hosted invitation-only Before User Created hook is unchanged. No Data API table-write permission is added.
