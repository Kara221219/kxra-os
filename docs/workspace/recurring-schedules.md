# Recurring local drafts

Implementation stage 0088; acceptance pending the current schedule CI, not inferred from historical queue tests. Daily schedules are local fixture drafts only. No hosted scheduler, service account, cron/OS service, webhook or external action is activated.

The room creator proposes an immutable definition and separately activates its exact revision. Changing a definition means proposing/reviewing a new ID and explicitly stopping the old one. Proposal pins the current prepared agent/message/thread/excerpts/skills/opted-in memories into a cancelled template job, atomically with the definition; that template never enters a worker queue after commit. A creator-only receipt shows the pinned agent/message and source counts. Its aggregate review digest is readable only while all pinned context remains authorised; source withdrawal or memory deletion returns a null digest. Ordinary schedules/occurrences obey the same active tenant/project/private-room membership rules as other workspace data. Owners cannot bypass private membership.

Definitions store an IANA zone, minute-precision daily wall time, local first date, expiry within 30 days and a 1–20 admitted-occurrence budget. At most 20 draft/active/paused definitions per person. No calendar-month/yearly/weekly expressions yet. UTC occurrence receipts remain visible next to local dates.

- A missing DST wall time records `DST_GAP`; an ambiguous wall time selects the earlier valid UTC instant. Offset sampling covers half-hour transitions and whole-day skips; tests exercise New York, London, Lord Howe, Apia and leap dates.
- Each authenticated drain ticks the current requester/current organisation before claiming at most one due job. Request IDs are deduplicated even for empty ticks. Unique `(schedule_id,local_day)` and `(schedule_id,scheduled_for)` prevent duplicate admissions; actor advisory locks serialize competing drains.
- Reconnect considers only the most recent due local day, never an accumulated backlog. Earlier missed dates are intentionally omitted. The occurrence stores the original scheduled instant; its catch-up job is immediately due. Pending queued/leased/dispatched children produce `OVERLAP` rather than another job; a full 20-active-job queue records `QUEUE_CAPACITY` without admission. Skips advance the cursor and are never retried for that date.
- Every admitted occurrence consumes budget, including failed/cancelled work. The final admission marks the definition `EXHAUSTED` while allowing that child to finish. Existing 20-run rolling daily and three-attempt pre-dispatch limits remain authoritative. Billing entitlement/financial budgets are separate unfinished work.
- Pause/revoke atomically cancels pending children, clears leases and cancels running output. The existing context guard now also gates schedule state/expiry and the immutable template's current identity/session/source permissions before dispatch/readiness/publication. It prevents late publication even if a worker retains a token. Completed runs retain their original scoped provenance/history policy.
- Scope withdrawal or uncertain dispatched outcome pauses an active definition during the requester's next tick. Scope withdrawal cancellation needs no new room access grant. Uncertain work cannot be resumed automatically: propose/review new work after investigation. Worker downtime means no ticks; there is no global unattended reaper. Source/expiry/publication fences still apply without a reaper.

Use Workspace → Jobs → Recurring drafts. Propose the daily definition, review the receipt and activate. Use Run next due draft or the explicit local fixture worker. Refresh recurring drafts to view receipts. A normal room member can read authorised metadata but cannot propose/review for the room creator, impersonate another requester or drain their work.

## Scoped audit export

The room creator can download metadata under Jobs → Audit metadata. `GET /api/team-space/:room/audit-export` checks current room membership/creator authority and authenticated RLS on every page. Maximum 500 events per CSV; the response's `X-KXRA-Next-Cursor` is an exact bigint cursor for the next earlier page. Query keys and duplicate/malformed/overflow cursors are rejected. Cursor pages are current-access snapshots; new later events do not disturb earlier IDs. There is no export of prompts, output, people, raw details, target/source identifiers, hashes, credentials or leases. Only event IDs/timestamps, allowlisted action names and safe state/boolean changes are included. Cells are quoted, escaped and protected against spreadsheet formulas. An aborted/unmounted browser request does not initiate a late download. No public URL or external storage/send is created. Actual HTTP pagination/negative cases and browser file download require this stage's CI acceptance.

### Catalog limits still to improve

The room API shows up to 100 definitions and up to 3,100 associated occurrence receipts; active definitions and exhausted definitions with pending children are prioritised, then paused/draft definitions and history. Jobs similarly prioritise queued/leased/dispatched work, then uncertain outcomes and completed history within their 100-entry cap. A populated regression proves older active controls remain ahead of 101 later archived definitions and cancelled jobs. Unbounded/history cursor pagination remains a customer-launch usability gate, particularly for larger rooms whose aggregate pending work could exceed a page. Current RLS and publication fences remain authoritative.
