## Contract and foreground entry point

[Official Codex App Server documentation](https://learn.chatgpt.com/docs/app-server), reviewed 3 November 2026, specifies `codex app-server --listen stdio://`, initialize/initialized, thread/start, turn/start, text item notifications and turn/completed. Installed-version schema generation is documented, but no installed/signed-in CLI or schema generator was invoked. The implementation deliberately accepts a narrow text subset; unknown events fail closed. Real installed-version compatibility remains unproven.

`packages/workspace/codex-stdio-transport.ts` takes an operator-selected absolute executable, dedicated working directory and explicit PATH/HOME/CODEX_HOME paths. It launches fixed arguments without a shell or inherited API/provider environment. It performs no executable discovery, installation, authentication, credential reading/copying, configuration writing or provider registration. Those paths cannot come from a model, task or remote HTTP body. Each generate call starts one foreground process only after the server acknowledges a fresh START. POSIX process groups are supervised; Windows is rejected pending a separate process-tree implementation. There is no detached daemon/unref/background installation: a separate Unix group exists solely to terminate the owned foreground process tree.

`paired-device-foreground.ts` is a newline-JSON foreground command interface:

- Start with `node --import tsx scripts/paired-device-foreground.ts --stub-only` for local synthetic acceptance. The stub mode forces the checked-in inert Node peer and `/tmp` paths.
- First input is strict SETUP with `origin`, `invitation`, `executable`, `workingDirectory` and `environment` containing only PATH/HOME/CODEX_HOME. The invitation must be a newly generated fixture invitation; never put one in a command argument, repository file or log.
- Subsequent commands are `{ "operation": "RECONNECT" }`, `{ "operation": "RUN_ONCE" }` and `{ "operation": "CLOSE" }`. Output contains finite state/errors and message receipts, never pairing/session secrets, provider stderr or drafts.
- The source also defines explicit `--codex-stdio` transport selection. **Do not execute that mode without separate action-specific approval and the live gates below.** It can launch the operator's real CLI and incur their provider usage. No live command was executed in this work.

The client currently permits literal loopback HTTP origins only, pins the API path, omits cookies, rejects redirects, bounds response bytes and deadlines and requires the server's FIXTURE_ONLY/unverified envelope. The existing API and database fixture guards remain in place. There is no production activation switch in this slice, no hosted bearer endpoint, TLS rollout or live credential installation. Pairing grants are generated only inside disposable synthetic fixtures.

## Lifecycle and authority

`PairedDeviceClient` retains the device session in process memory. REDEEM is attempted once; an ambiguous response requires a fresh owner invitation/new client rather than reusing the code. Reconnect performs an explicit heartbeat only; it never starts a task. RUN_ONCE performs one poll/start/generate/result cycle. Concurrent commands/runs are refused. Close forgets local credentials and aborts active generation; it is not a substitute for the owner's authenticated server REVOKE.

During one active foreground cycle, a bounded sequential heartbeat/status monitor checks current session and exact task/fence. Cancellation aborts the process; revocation/expiry/membership loss discards the local session. Network or process loss, result loss and uncertain dispatch never replay inference. A provider may already have billed before cancellation; stopping the owned process cannot retract a completed request. The server remains authoritative for immutable tenant, owner, agent, room, thread, session revision, reviewed source hash, lease and publication binding. Device tokens cannot authenticate customer cookie endpoints or connector management.

The protocol requests read-only access with restricted empty roots and untrusted approvals, never answers a tool request, bounds stream/events/draft/stderr and rejects foreign context and non-text/tool items. These are protocol controls, **not proof that an arbitrary CLI or installed extensions cannot execute tools**. HOME/CODEX_HOME may contain sensitive user configuration; this code does not inspect them or prove them safe. A separately accepted process sandbox/configuration and deny-all tools policy are required before live execution. Normal model user/reasoning items can be consumed without becoming output; only one bounded agent message is published.
