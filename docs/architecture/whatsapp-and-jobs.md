# WhatsApp and worker foundations

The approved target remains Meta WhatsApp Business Cloud API with Sol as the ordinary partner capability and optional owner-authorized Astra escalation. Available API IDs, contracts and data-processing terms must be verified before enabling provider calls; desktop model labels are not proof of public API availability.

Implemented now: raw-body HMAC verification helper; strict E.164 hashing; one-use, expiry/attempt-bounded account challenges; exact WABA/number pairing; explicit project selection; worker-only deduplicated ingress; closed supported intents; media quarantine/voice-consent state; takeover/revocation checks; and disabled outbound intents. PostgreSQL rechecks account/legal/membership/project authority. Authenticated challenge/project/revoke APIs and redacted status UI exist. There is no registered webhook, provider media download, production scan/transcription, LLM call or outbound send.

Required delivery sequence: verify provider signature over exact bytes → deduplicate provider event → resolve verified phone/account pairing in server code → verify active account/current project assignment → select explicit authorized project or ask for disambiguation → retrieve only authorized shared data → call model with scoped evidence and tool allowlist → validate citations/output → recheck pairing and project authorization before send → log actual delivery result. Never use a model to resolve authorization. Revoked pairings, stale assignment versions, ambiguous project choices and unsigned/replayed requests must fail closed.

Documents/images/voice notes require authenticated media fetch with allowlisted provider origins, bounded size/type, quarantine scanning, approved retention and transcription consent. Task proposals and ideas are drafts; no financial spend, publishing, membership change or trading authority comes from chat text.

Trigger.dev remains the hosted dispatch target, but no task or schedule is registered with it. The local routine engine now stores exact approved versions, unique logical slots/events, service/project scope, leases, checkpoints, bounded retry/recovery, outcomes and disabled notification intents in PostgreSQL. Its worker contract reauthorizes current manifest/version/service state before retry and preserves checkpoints after lease expiry. It does not create an external send or provider action.

Before hosted dispatch, map each reviewed routine action to a narrowly scoped worker capability, register only exact approved versions, keep schedules disabled until staging acceptance, and prove Trigger.dev deduplication/cancellation/crash behavior against the PostgreSQL authority. WhatsApp jobs additionally require the pairing and current-project checks above. No job may infer actor, tenant, project, budget or delivery authority from its payload or model output.
